# Informacion Certificación

La cert `HTB Certified Penetration Testing Specialist (CPTS)` de Hack The Box tiene un precio base de `$210 USD` por el examen, que incluye dos intentos. Sin embargo, para acceder a la prueba es obligatorio completar primero el `PATH` de 28 módulos en HTB Academy. 

El costo total depende del método elegido para estudiar: la opción más recomendada es el Plan Anual Silver de $490 USD, que cubre todos los módulos necesarios e incluye el cupón del examen sin costo extra. 

Si eres estudiante y tienes un correo académico, la suscripción mensual te costará unos $96 USD al año y el examen $210 USD, sumando un total aproximado de $306 USD. 

También existe la opción de comprar módulos de forma individual mediante "cubos", lo cual suele rentar solo si te lleva mucho el proceso, si te toma varios meses finalizar el temario. 

El examen es completamente práctico, dura 10 días en total y simula una red corporativa real que requiere técnicas avanzadas de Active Directory, pivoting, evasión, hacking web. 

Los primeros 5 días se dedican a la fase de hackeo en los laboratorios y los siguientes 5 días a la redacción de un `informe técnico profesional` que es evaluado manualmente de forma muy estricta. 

Al compararla con la certificación OSCP de OffSec, la CPTS destaca por ser significativamente más económica (cerca de $490 USD frente a los más de $1,700 USD de la competencia) y por ofrecer un contenido teórico mucho más profundo y actualizado.

A pesar de que el `OSCP` sigue manteniendo una mayor reputación histórica para superar los filtros iniciales de recursos humanos, la CPTS se ha consolidado rápidamente en el sector como una de las mejores opciones del mercado para adquirir habilidades técnicas reales de nivel profesional.

# Enumeracion Inicial

La fase de enumeración es la primera etapa de cualquier `pentester` y trata de recopilar información para abrir un vector de ataque. Para ello vamos a empezar recopilando informaciones de dominios. Para poder ver certificados `SSL` que incluyan varios `dominios/subdominios` o datos históricos.

## Recopilacion de informacion en un dominio

Para esto tenemos la página **https://crt.sh**

Búsqueda básica en **navegador**:

```sh
https://crt.sh/?q=ejemplo.com
```

`JSON` output para parsear (necesario jq)

```sh
curl -s https://crt.sh/\?q\=ejemplo.com\&output\=json | jq .
```

Y si queremos extraer únicamente los `subdominios`:

```sh
curl -s https://crt.sh/\?q\=example.com\&output\=json | jq . | grep name | cut -d":" -f2 | grep -v "CN=" | cut -d'"' -f2 | awk '{gsub(/\\n/,"\n");}1;' | sort -u
```

Ejemplo de el `output` esperado:

```sh
account.ejemplo.com
blog.ejemplo.com
bots.ejemplo.com
console.ejemplo.com
ct.ejemplo.com
data.ejemplo.com
*.ejemplo.com
ejemplo.com
integrations.ejemplo.com
iot.ejemplo.com
mails.ejemplo.com
luis.ejemplo.com
marina.ejemplo.com
```

Para crear una lista con `subdominios` accesibles

```sh
curl -s https://crt.sh/\?q\=example.com\&output\=json | jq . | grep name | cut -d":" -f2 | grep -v "CN=" | cut -d'"' -f2 | awk '{gsub(/\\n/,"\n");}1;' | sort -u > subdomainlist
```

Ahora teniendo esto para encontrar `hosts` basándose en la `IP`:

```sh
for i in $(cat subdomainlist);do host $i | grep "has address" | grep example.com | cut -d" " -f1,4;done
```

Para extraer la `IP` solamente:

```sh
for i in $(cat subdomainlist);do host $i | grep "has address" | grep example.com | cut -d" " -f4 >> ip-addresses.txt;done
```

También tenemos otra herramienta bastante interesante llamada `shodan`, que nos sirve para ver servicios o puertos, datos de geolocalización, datos históticos de web etc...

Un `escaneo básico con shodan`

```sh
shodan host 192.168.1.0
```

Y para una lista de `IPs`

```sh
for i in $(cat ip-addresses.txt);do shodan host $i;done
```

Un ejemplo de `output` de un escaneo con `shodan`

```sh
10.10.10.10
City:                    Madrid
Country:                 Spain
Organization:            Sanidad...
Updated:                 2026-09-01T15:39:55.446281
Number of open ports:    8

Ports:
     25/tcp  SMTP
     53/tcp  DNS
     53/udp  DNS  
     80/tcp  Apache httpd 
     81/tcp  Apache httpd 
    110/tcp  POP3
    111/tcp  RPCbind
    443/tcp  Apache httpd 
    444/tcp  Unknown
```

Es bastante `potente` por que nos revela servidores web en este caso con `Apache`, servidores de `correo electrónico`, servicios `DNS` y `RDP`

## Enumeracion DNS

`DNS` (Domain Name System) es una parte importante de `Internet` que traduce los nombres de `dominios` en direcciones `IP`. El `DNS` funciona sin una `db` central. Toda la información se pasa en miles de servidores de nombres a nivel mundial. 

Para `Pentesting`, la enumeración `DNS` es fundamental para descubrir `subdominios`, servidores de `correo` y estructura `interna`.

Componentes clave de `DNS`

- Servidor raíz `DNS`: Es responsable de los `dominios` de nivel superior o `TLD`.

- Servidores de `nombres autorizados`: Mantener privilegio a zonas específicas. Proporcionar info.

- Servidores de `nombres no autorizados`: Recopila información a través de consultas **recursivas**.

- Almacenamiento en `caché` de servers DNS: Reenvío de consultas DNS a otros servidores `DNS`.

- Servidores de reenvío: Reenvío de consultas `DNS` a otros servidores `DNS`.

- `Resuelvos`: Realizar resolución `DNS` a nombres locales.

Tipos de registro `DNS`:

| Tipo de registro | Descripción |
|---|---|
| A | Devuelve la dirección IPv4 del dominio solicitado |
| AAAA | Devuelve la dirección IPv6 del dominio solicitado |
| MX | Devuelve servidores de correo responsables |
| NS | Devuelve servidores DNS (servidores de nombres) del dominio |
| TXT | Contiene información diversa (SPF, DMARC, registros de verificación) |
| CNAME | Registro de alias que apunta a otro nombre de dominio |
| PTR | Búsqueda inversa - convierte las direcciones IP en nombres de dominio |
| SOA | Inicio de la autoridad - proporciona información de la zona y contacto del administrador |

Algunos archivos de configuración de `BIND9`

```sh
# Las ubicaciones principales en Linux
/etc/bind/named.conf.local    
/etc/bind/named.conf.options  
/etc/bind/named.conf.log      
```

Consultas `DNS` básicas con los registros que vimos antes.

```sh
dig A dominio.com
dig AAAA dominio.com
dig MX dominio.com
dig NS dominio.com
dig TXT dominio.com
dig SOA dominio.com
```

Si queremos consultar un Servidor DNS específico:

```sh
dig @dns-server dominio.com
```

Y si queremos ver todos los `registros`:

```sh
dig ANY dominio.com @dns-server
```

Descubrir nombres de servidores con el `dominio`:

```sh
dig NS dominio.com @10.10.10.10
```

A varios `servers`:

```sh
dig @ns1.dominio.com dominio.com
dig @ns2.dominio.com dominio.com
```

Para descubrimiento de `subdominios`:

```sh
for sub in $(cat subdomains.txt); do
    dig $sub.dominio.com @dns-server | grep -v ';' | grep $sub
done
```

Usando la herramienta `DNSenum`:

```sh
dnsenum --dnsserver 10.10.10.10 --enum -p 0 -s 0 -o subdomains.txt -f /opt/useful/seclists/Discovery/DNS/subdomains-top1million-110000.txt dominio.com
```

Usando `fierce`:

```sh
fierce -dns dominio.com

# Usando wordlist

fierce -dns dominio.com -wordlist wordlist.txt
```

Usando `sublist3r`:

```sh
sublist3r -d dominio.com
sublist3r -d dominio.com -t 10 -o subdomains.txt
```

Para buscar servidores de `email`:

```sh
dig MX dominio.com
dig mail.dominio.com
dig smtp.dominio.com
dig pop.dominio.com
dig imap.dominio.com
```
